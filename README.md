# VibeReading

独立运行的本地代码阅读 GUI。选择代码目录后，按 **项目 → 文件 → 函数** 阅读代码，并沿函数调用关系跳转。类（class）和模块作为可点击标签筛选，避免增加一层必须展开的结构。你可以继续在 VS Code、RStudio 或其他编辑器中写代码；阅读器根据保存到磁盘的文件刷新。

界面通过浏览器访问本机服务。代码解析使用本地语法库，不需要编辑器插件、语言服务器、AI 服务或被阅读语言的编译器。阅读器不执行被扫描的源代码，也不修改被扫描的项目；人工说明和审核版本存放在 VibeReading 自己的状态目录。

这是静态代码阅读工具。函数之间的一条线表示代码中发现的调用关系；它不证明函数必然运行，不证明算法正确，也不代替项目测试。

## 启动

需要 Python 3.12。首次安装会创建项目自己的 `.venv`，按 `requirements.txt` 安装锁定版本的语法解析依赖；不修改全局 Python 环境。首次下载依赖需要网络，安装后本地读取和浏览不依赖外部服务。

在 VibeReading 目录打开 PowerShell：

```powershell
# 首次安装；ExecutionPolicy 仅对本次 PowerShell 进程生效。
powershell -NoProfile -ExecutionPolicy Bypass -File .\setup.ps1

# 使用本地环境打开随项目提供的多语言示例。
.\.venv\Scripts\python.exe run.py --project examples/polyglot
```

🖱️ 也可以双击 `start.cmd` 使用启动入口。若已经激活安装好依赖的 Python 环境，可以运行：

```powershell
python run.py --project examples/polyglot
```

指定自己的代码目录时，给有空格的路径加引号：

```powershell
# 把路径换成要阅读的代码目录；程序只读取这个目录中的源文件。
.\.venv\Scripts\python.exe run.py --project "D:\YourProject"
```

服务终端应保持运行。关闭服务时在该终端按 `Ctrl+C`。浏览器窗口关闭本身不等于服务停止。

## 如何阅读

1. 选择项目目录，查看按文件分组的函数。可以搜索名称、筛选语言或点击类/模块标签。
2. 点击函数，查看源码、位置、提取的注释，以及“调用谁”和“被谁调用”。图中的箭头从调用方指向被调用方。
3. 沿关系点击其他函数，核对调用位置及其输入输出。不同文件中的同名函数应保持为不同节点。
4. 在编辑器保存文件。服务大约每秒检查一次变化，浏览器随扫描结果刷新；未保存的编辑内容不在读取范围内。
5. 在结构化说明中填写用途、输入、输出和注意事项。明确人工核对后再批准；以后代码变化时继续复核。

大项目和较长文件的扫描耗时会影响刷新速度；这里的“保存后刷新”不是毫秒级同步。正在编辑的说明需要先保存或处理冲突，以免用过期内容覆盖新版本。

### 关系的确定程度

| 标记 | 阅读方式 |
| --- | --- |
| 已解析（resolved） | 静态规则能把这次调用定位到一个项目内定义；仍然不是运行时验证。 |
| 候选（candidate） | 有可能对应某个定义，但导入路径、作用域或动态行为还需要确认。 |
| 未解析（unresolved） | 无法可靠定位，例如动态属性、外部库、函数指针或反射调用；保留调用位置和原因。 |

出现候选或未解析并不等于代码有错误。外部标准库调用也可能显示为未解析。相反，一条已解析连线也不能说明该函数中的检查、统计方法或单位正确。

## 函数说明与人工审批

阅读器提取源码里的 docstring、文档注释等文字；这些是作者提供的原始说明，不自动获得人工审核状态。建议让 AI 写代码时同时填写以下四项，人工也可直接在阅读器中补充：

| 字段 | 应填写什么 |
| --- | --- |
| 用途（summary） | 这个函数具体完成什么任务。 |
| 输入（inputs） | 参数的含义、类型、单位、允许范围和缺失值约定。 |
| 输出（outputs） | 返回结构、单位、特殊值以及如何解释。 |
| 注意（notes） | 假设、异常处理、证据、疑点和待验证事项。 |

Python 示例：

```python
def distance(x, y):
    """用途：计算二维向量长度。
    输入：同一长度单位下的平面坐标 x、y。
    输出：与输入同单位的非负长度。
    注意：不能直接用于经纬度；调用方需要处理缺失值。
    """
    return (x * x + y * y) ** 0.5
```

Java/C/C++/JavaScript/TypeScript 可使用 `/** ... */`，Rust 可使用 `///`，Go 可使用 `//`，R 可使用 `#'` 写相同字段。字段标签帮助阅读；注释里的“已审批”字样没有审批效力。

人工说明和提取注释分开保存。说明记录来源、版本以及关联代码摘要（hash）；AI 导入的说明只作为草稿。批准需要明确的人工操作。关联代码改变后，旧说明保留，但批准状态需要复核。代码摘要采取保守策略，同一文件其他内容变化也可能触发复核。

注释导入/导出应使用应用返回的函数 ID，不能只按函数名匹配，因为不同文件可以有同名函数。`.vibereading/state.sqlite3` 位于 **VibeReading 应用目录**，保存说明及历史；它不写入被阅读的项目。备份阅读记录时，应在服务停止后一起备份这个状态目录。

## 多语言示例与核对

`examples/polyglot/` 提供九种语言的独立小例子，均以声明函数为主，不调用网络、文件写入或外部服务。

| 语言 | 示例位置 | 主要检查点 |
| --- | --- | --- |
| Python | `python/main.py`、`geometry.py`、`labels.py` | 两个同名 `norm`、显式 import、别名和跨文件关系。 |
| R | `r/measurements.R` | `<- function(...)` 定义和普通函数调用。 |
| Java | `java/Measurements.java` | 同一类的静态方法及类标签。 |
| C | `c/measurements.c` | 普通函数定义和直接调用。 |
| C++ | `cpp/measurements.cpp` | 基础函数定义和直接调用。 |
| Rust | `rust/measurements.rs` | `pub fn` 定义和直接调用。 |
| JavaScript | `javascript/measurements.js` | 普通函数定义和直接调用。 |
| TypeScript | `typescript/measurements.ts` | 带类型标注的函数定义。 |
| Go | `go/measurements.go` | 包文件里的普通函数调用。 |

预期共 **27 个函数、18 对不同的内部调用关系**；同一函数对可能有多次调用。这些数值来自示例清单，不能当成测试通过记录。机器可读清单在 `examples/expected.json`。Python 子目录作为独立扫描根时，可明确定位两次 import；整体扫描 `polyglot` 时，同目录脚本导入可能保守显示为候选，因为 Python 的运行目录和 `sys.path` 会影响实际导入。

建议第一次使用按以下顺序核对：

1. 确认九种语言都出现，并找到 Java 的 `Measurements` 类标签。
2. 从各语言的比较函数跳到汇总函数，再跳到缩放函数。
3. 查看 Python 的 `analyse_point`，确认两条边指向不同文件中的 `norm`。
4. 在示例副本里添加或修改一个函数并保存，观察结构刷新与选中状态。
5. 给函数写一条人工说明，批准后修改关联代码，检查旧记录被保留并提示复核。

验证应分别记录语法提取、调用解析、保存后刷新、说明持久化和界面行为；某一项通过不代表其余项通过。具体本次验证结果以实际测试输出和实施记录为准。

## 已知边界

- 语言适配器面向常用函数/方法语法。支持一种语言不等于完整实现该语言的编译器、类型系统或所有语法形式。
- 多态、重载、宏、条件编译、反射、装饰器、运行时赋值、函数指针和动态导入可能使关系不完整或不确定。R 的动态环境与非标准求值也需要特别谨慎。
- 图优先展示可理解的局部关系；项目较大时需要筛选。界面显示范围不等于整个项目的全部调用。
- 语法错误需要明确显示；编辑过程中暂时写坏的文件不应被解释为“没有函数”。
- 扫描上限为 1,500 个受支持的源文件、每文件 1 MiB。忽略符号链接和 `.git`、`.venv`、`node_modules`、`__pycache__`、`target`、`build`、`dist`、`.vibereading`、`work` 等生成目录。
- 本地端口只用于本机浏览，不是多人协作平台；没有云同步。人工批准表示已审核这条说明与当时的代码，不构成科学结论或安全性的证明。
